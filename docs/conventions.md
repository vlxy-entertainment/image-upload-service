# Codebase Conventions

This is a deliberately small service. Conventions reflect that — favor a single
readable file over premature layering.

## Structure

```
src/
  index.ts          # entire Express app: middleware, routes, upload logic
  config/env.ts     # Zod-validated, fail-fast env loading
  types/
    tiktok.ts       # hand-written TikTok request/response types
    supabase.ts     # GENERATED by the Supabase CLI — do not hand-edit
dist/               # tsc output, gitignored (local build artifacts)
docs/               # this documentation
```

- **One-file app.** All routing, middleware, and the upload pipeline live in
  `src/index.ts`. There is no controller/service/router split yet — if the service
  grows (e.g. real account-management endpoints), that is the natural first
  refactor boundary.

## TypeScript

- `tsconfig.json` is **loose**: `strict: false`, `noImplicitAny: false`,
  `noUnusedLocals: false`, etc. Target ES2020, CommonJS modules. Don't assume
  strict-mode guarantees when editing.
- Non-null assertions (`account.csrftoken!`) are used where a prior query
  guarantees presence.
- Generated `supabase.ts` provides the `Database`, `Tables<>`, `TablesUpdate<>`,
  `Enums<>` helpers. Use `Tables<'tiktok_accounts'>` etc. rather than redefining
  row shapes. Regenerate via the Supabase CLI rather than editing by hand.

## Configuration

- All env access goes through the validated `env` object exported from
  `src/config/env.ts` — **never read `process.env` directly** elsewhere.
- Validation is fail-fast: a missing/invalid var prints the Zod errors and calls
  `process.exit(1)` at startup. Add new config by extending `envSchema`.

## Logging & responses

- Plain `console.log` / `console.error`, often prefixed with emoji
  (`🚀 🔧 📊 📤 🚫 ❌ ✅`). The upload path logs each stage verbosely — intentional,
  given the opaque TikTok upstream.
- Error responses are **structured JSON**, not bare statuses. Keep the established
  shape (`error: true`, `statusCode`, `statusMessage`, `message`, plus context
  objects) — see [architecture.md](architecture.md). Success responses stay minimal.

## Tooling

- **pnpm** is the package manager (`pnpm-lock.yaml` committed); the Dockerfile
  falls back to npm only if no pnpm lockfile is present.
- No test framework is set up — `npm test` is a placeholder that exits non-zero.
- Node version is pinned (`engines: node 24.10.0`) and matched by the Docker base
  image `node:24.10.0-alpine`.

## Things to leave alone / be careful with

- `src/types/supabase.ts` — generated; regenerate, don't edit.
- `dist/` — build output; the orphaned `dist/scripts/*` are stale artifacts from
  the parent project (no `src` counterpart) and should not be treated as part of
  this service.
